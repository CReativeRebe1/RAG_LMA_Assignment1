# RAG: Baseline Dense Retrieval vs. Cross-Encoder Re-Ranking

Two retrieval-augmented generation pipelines over India's **Digital Personal Data Protection Act, 2023**.

- **Pipeline 1 (baseline):** the bi-encoder `all-MiniLM-L6-v2` + a FAISS index retrieve the top-10; the top-3 go to the LLM and give Answer 1.
- **Pipeline 2 (re-ranking):** the same top-10 are re-scored by the cross-encoder `ms-marco-MiniLM-L-6-v2`; the new top-3 go to the LLM and give Answer 2.

All code is in **`rag_baseline_vs_rerank.ipynb`**.

## Files
| Path | What |
|---|---|
| `rag_baseline_vs_rerank.ipynb` | the full pipeline, evaluation and latency profiling |
| `data/dpdp_act_2023.pdf` | the official Gazette copy of the Act |
| `results/` | chunks, rank-shift table, metrics, latency, LLM answers, figures (generated by the notebook) |
| `FLOW.md` | data and function flow |

## Running
```bash
pip install -r requirements.txt
# free key from https://console.groq.com/keys, put in a .env file (repo folder or its parent):
#   GROQ_API_KEY=gsk_...
jupyter notebook rag_baseline_vs_rerank.ipynb     # then Run All
```
- A CUDA GPU is used if available; otherwise everything runs on the CPU (slower latency numbers).
- LLM answers are cached in `results/llm_cache.json`, so a re-run reproduces the same answers without calling the API again.
- The generator is `openai/gpt-oss-120b` served by Groq; set `LLM_MODEL` to use a different Groq model.
- `.env` is git-ignored and must never be committed.
